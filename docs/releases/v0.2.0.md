# v0.2.0 release notes

Status: local development version. No `v0.2.0` tag, pushed release, or package
publication is claimed. Publication readiness is **BLOCKED** until the exact
release commit completes the full post-push CI workflow.

## Scope

`v0.2.0` adds CPython `3.14` to the supported portable runtime range alongside
`3.11`–`3.13`. The skill remains monochrome-only and VTracer-first. Its
canonical renderer contract, acceptance model `1.0.3`, schemas, synthetic
corpus, fixtures, and goldens are unchanged from `v0.1.0`.

## Python compatibility contract

- Package metadata accepts CPython `>=3.11,<3.15`; the tested contract covers
  standard GIL-enabled builds, not the separate free-threaded `t` ABI.
- The Ubuntu `24.04` portable CI matrix runs the complete portable suite,
  validators, leak scan, and deterministic release build on `3.11`, `3.12`,
  `3.13`, and `3.14`.
- `requirements-lock.txt` remains mandatory with `--require-hashes`; Python
  `3.14` support does not weaken or bypass the dependency lock.
- The canonical Linux x64 and Darwin arm64 jobs remain pinned to Python `3.11`
  because Python is orchestration for those jobs, not part of the unchanged
  Node/WASM rendering identity. Portable Python `3.14` compatibility is tested
  separately in the matrix.

## Release artifacts to build

```text
reconstructing-raster-icons-v0.2.0.zip
reconstructing-raster-icons-v0.2.0.zip.sha256
```

The ZIP contract is unchanged: two builds and adjacent checksums must be
byte-identical, and only paths listed in `release-manifest.txt` are included.
Internal task records remain development-tree material and are not packaged.

## Verification boundary

The pre-change package rejection was reproduced with the official CPython
`3.14.7` source release on Darwin arm64: project metadata rejected `3.14.7`
because the previous upper bound was `<3.14`. The same isolated runtime can
install the current hash-locked Darwin arm64 dependency wheels for macOS 14 or
newer, build and install the `0.2.0` project, and pass all `302` portable tests
with the single expected Linux-only skip. The canonical Darwin arm64 suite
also passed with zero skips under Python `3.14.7`. SciPy `1.17.1` does not
provide a matching CPython `3.14` wheel tagged for macOS 11 arm64, so this is
not a claim of Python `3.14` support on older macOS releases.

The prior-runtime Python `3.12.13` regression run also passed. Of its `302`
portable tests, `299` ran in the protected source tree and the three tests that
intentionally write beside the repository passed in an identical writable
copy; the Linux-only startup gate was the sole expected skip.

Local Darwin evidence does not prove the Ubuntu Python `3.14` job or the
canonical Linux x64 job. Those Linux results remain **UNVERIFIED** for `0.2.0`
until GitHub Actions completes on the exact release commit with zero unexpected
skips. The post-push canonical Darwin job also remains **UNVERIFIED** even
though the equivalent native local suite passed.
